2. 暗壳科技 ｜ 高级算法应用工程师（AIGC 与 3D 重建）

技术 天使轮 · AI 空间设计工作台 Lovspark · 腾讯设计 AIGC 联合实验室

一句话定位

把 AI 生成能力工程化落地——让"文字描述一个房间"变成"输出可用的 3D 模型"。

核心职责

  1. 从文本/图像生成 3D 资产（Mesh/Texture）的算法研发与优化
  2. 3D 与物理引擎集成，让生成模型可交互
  3. Python + Docker 容器化，搭建高可用生成式 AI 系统
  4. 跟踪 NeRF、Gaussian Splatting、3D Diffusion 前沿技术

必备技能

  • Python 精通 + PyTorch
  • ControlNet / LoRA / CLIP（AIGC 核心技术栈）
  • 3D 重建（NeRF / 3D Gaussian Splatting / SLAM）
  • Docker 容器化 + CI/CD
  • 跨团队协作（需和 Unity/Unreal 引擎团队配合）

人才画像：硕士起步（博士优先），3年+ AIGC 或 3D 视觉开发经验。能把论文变成服务的工程师。

3. 暗壳科技 ｜ 高级算法工程师（Physical AI & World Model）

技术 天使轮 · AI 空间设计工作台

一句话定位

让 AI 不只"看到"空间，还能"理解"空间的物理规律。

核心职责

  1. 构建融合视觉生成与物理仿真的 World Model
  2. 把建材物理参数（力学/热学/声学/光学）注入生成模型
  3. 搭建具身智能仿真环境，训练 Agent 做空间交互
  4. 时空图神经网络 / Agent-Based Modeling 跨尺度推演

专业术语

  • World Model：能模拟因果关系的系统，不只是生成图像
  • Physical AI：让 AI 具备物理常识，生成结果物理上说得通
  • PINNs：把物理方程嵌入神经网络训练，输出天然符合物理规律
  • Embodied Agent：有"身体"的 AI 智能体，能在环境中行动和交互

必备技能

  • PyTorch / JAX + 物理仿真引擎（MuJoCo / PyBullet / Taichi / NVIDIA Omniverse）
  • 3D Vision（NeRF / 3DGS / SLAM）
  • 强化学习 / 模仿学习基础
  • 物理属性与视觉生成的联合优化

人才画像：博士优先，纯研究型但需能工程化落地。同时理解计算机视觉和物理世界的稀缺复合背景。

一、AI 公司为什么需要这些岗位？

1. 技术层岗位——解决"能不能做"的问题

需求为什么需要举例
模型能力大模型需要持续训练、微调、优化阿里通义多模态交互
工程化落地论文 ≠ 能上线的服务暗壳科技 JD-01
物理世界理解纯视觉生成不够，需要理解物理规律暗壳科技 JD-02
硬件集成AI 需要跑在具体设备上可触未来 LOOI 机器人
数据基础好模型需要好数据光轮智能（合成数据）
启示：AI 不是"调个 API"就行的，背后需要完整的工程体系。做项目时要理解——你的产品不是漂浮在空中的想法，而是需要落地到具体技术实现。

2. 产品层岗位——解决"做什么"的问题

需求为什么需要举例
场景定义技术能做 100 件事，但用户只需要 3 件腾娱互动（让美术用 AI 提效）
用户体验AI 再强，用户不会用/不想用就白搭可触未来（情感化交互）
安全合规AI 输出可能有害，需要人来把关阶跃星辰安全方向
商业化技术价值需要翻译成商业价值飞书解决方案专家
启示：做项目时不要只问"AI 能做什么"，而要问"用户需要什么、AI 怎么帮他"。产品经理思维是把技术变成价值的桥梁。

3. 运营层岗位——解决"怎么让人用"的问题

需求为什么需要举例
用户获取好产品也需要被看见暗壳科技海外增长
内容传播需要让用户看到"能帮我做什么"暗壳科技海外内容策划
社区建设开发者/用户社区是最持久的增长飞轮SandBase AI
用户激活注册≠使用，需要引导用户完成"啊哈时刻"阿里百炼产品运营

4. 销售/BD 层岗位——解决"怎么赚钱"的问题

需求为什么需要举例
商业闭环技术再好，没有收入公司就活不下去微软小冰销售总监
客户理解企业客户需要的是"解决我问题的方案"飞书解决方案专家
渠道建设光靠直销覆盖不了市场小冰要求微盟/有赞渠道经验

二、好项目标准（从招聘要求反推）

好项目 = 解决真实问题 × 技术可行 × 用户体验好 × 能落地 × 有商业/社会价值

标准 1：解决真实问题

招聘体现：暗壳科技（设计师需要快速出3D方案）、心跃智能（心理咨询师需要提效）、腾娱互动（美术团队重复劳动多）

比赛中：评委第一个问题——"你解决的是什么问题？"

  • 你说的"问题"是真实存在的吗？你观察过/问过目标用户吗？
  • 这个问题现在怎么解决的？现有方案有什么不足？
  • 你的方案比现有方案好在哪里？好多少？

标准 2：技术可行

招聘体现：所有算法岗都要求"工程化落地能力"——论文 ≠ 产品

比赛中：评委第二个问题——"你怎么实现的？能跑吗？"

  • 你的技术方案是什么？用了哪些模型/API/框架？
  • 你的原型能跑通核心功能吗？
  • 你知道你的方案的局限性在哪里吗？

标准 3：用户体验好

招聘体现：可触未来产品经理要求"对糟糕的产品容忍度低"

比赛中：评委第三个问题——"用户体验怎么样？"

  • 主流程是什么？几步能完成核心任务？
  • 你让目标用户试用过吗？他们第一反应是什么？
  • 界面/交互是否简洁直观？

标准 4：能落地

招聘体现：几乎所有岗位都要求"推动落地""交付能力""结果导向"

比赛中：评委第四个问题——"这个东西能推广/量产/持续运营吗？"

  • MVP 是什么？最小投入能做出什么？
  • 如果要推广，第一步做什么？找谁合作？
  • 有没有成本估算？

标准 5：有商业/社会价值

招聘体现：所有公司都在回答"我的产品能为谁创造什么价值？"

比赛中：评委第五个问题——"这个项目有什么价值？"

  • 你的项目创造了什么价值？用一句话说清楚。
  • 这个价值是可衡量的吗？
  • 如果持续运营，商业模式是什么？

三、比赛评选标准参考

维度权重（参考）评委关注点
问题定义20-25%问题是否真实、具体、有价值
技术实现20-25%方案是否可行、是否有技术深度
创新性15-20%是否有独特视角或新颖方案
用户体验15-20%产品是否好用、交互是否流畅
完成度10-15%能否演示、核心功能是否跑通
展示表达5-10%能否清晰说明做了什么、为什么做
可扩展性5-10%未来能否推广、迭代、商业化

不同类型比赛的侧重点

  • 微课比赛/教育类：教育价值、内容质量、交互设计。AI 的角色是辅助工具，不是"用 AI 做课件"，而是"AI 如何提升学习效果"
  • 黑客松/创新赛：问题定义、创新性、完成度、演示效果。48 小时内要做出能演示的原型，选题要小而精准
  • 科创赛/工程类：技术深度、工程实现、数据支撑。需要有实验数据、对比分析、技术文档

四、从想法到产品的五步流程

定义问题(1-2天) → 调研方案(1天) → 设计原型(1-2天) → 开发MVP(3-7天) → 测试迭代(持续)

第一步：定义问题

明确目标用户、使用场景、核心痛点。产出一段话描述项目（"为 XX 用户解决 XX 问题"）。找 3-5 个目标用户确认问题是否真实存在。

第二步：调研方案

看看别人怎么解决类似问题。不需要原创技术——用现成的 AI API + 独特的场景理解 = 好项目。

第三步：设计原型

先设计再开发。用 Figma/Axure/纸笔画出产品长什么样、用户怎么用。

第四步：开发 MVP

用最小投入做出能跑通核心功能的版本。技术选型参考：

  • 网页应用：HTML/CSS/JS + AI API
  • 移动应用：微信小程序 / uni-app
  • 硬件产品：Arduino/ESP32 + 传感器 + AI 接口
  • AI 能力：通义千问 API / 百度文心 / OpenAI / 开源模型

第五步：测试迭代

让真实用户使用，收集反馈，持续改进。比赛前至少迭代 2-3 轮。

五、产品标准自评表

维度1分（基础）3分（良好）5分（优秀）
问题定义有一个模糊的想法明确了用户和场景有用户调研数据支撑
技术实现调用了 API有自定义逻辑和优化有技术创新或独特方案
用户体验能用但不直观主流程清晰用户无需指导即可上手
完成度有 PPT能演示核心功能有完整 MVP + 迭代记录
价值有趣解决了真实问题有可量化的价值 + 扩展路径

六、关键提醒

  • 技术可行性优先：先确认技术能做到，再设计产品形态
  • 问题驱动而非技术驱动：从真实需求出发，不从"我会什么"出发
  • 可落地比可演示更重要：评委看重的是"能不能真的用起来"
  • 安全和合规是底线：AI 项目必须考虑内容安全、隐私保护
  • 运营和传播是加分项：好的项目需要好的故事来传递价值
  • 从小切口入手：不要试图"改变世界"，先做一个"帮一个人解决一个问题"的小工具
  • 让孩子参与全过程：不是妈妈做、孩子看，而是孩子主导、妈妈辅助
  • 重视展示和表达：比赛不只是看产品，也看能不能讲清楚
最重要的一句话：好项目不是技术最先进的，而是最能解决真实问题的。AI 是工具，问题是核心。

获奖作品共性分析

技术层面

  • 不是技术最先进的获奖，而是最能解决问题的获奖
  • 调用现有 API + 独特场景理解 = 好项目（不需要自己训练模型）
  • 工程化能力是硬门槛——能跑通 > 概念好

产品层面

  • 小闭环 > 大平台——场景真实、结构清晰、证据完整
  • 用户体验决定第一印象——评委看到 demo 的前 30 秒很重要
  • 完成度是底线——半成品再好也不如能跑通的 MVP

展示层面

  • 讲清楚"为什么做"比"做了什么"更重要
  • 过程记录是加分项——从想法到成品的完整路径
  • 答辩能力 = 说服能力——技术再好，讲不明白就白搭

团队层面

  • 专业互补 > 个人全能——AdventureX 获奖团队是跨校跨专业组合
  • 分工明确 + 沟通高效——120 小时极限开发考验协作

关键提醒

  1. 原创性是底线——所有赛事都强调原创，抄袭直接取消资格
  2. 展示能力很重要——再好的项目，讲不明白就白搭
  3. 小而精 > 大而全——评委更喜欢"解决一个小问题"而不是"改变世界"
  4. 过程比结果重要——很多赛事看重从想法到成品的思考过程
  5. 用户体验是第一印象——demo 的前 30 秒决定评委的第一判断
  6. 不要堆功能——功能多不如核心功能体验好
  7. 提前准备答辩——技术再好，讲不明白就浪费了
